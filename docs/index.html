      03 / THE TRADE-OFFS

      值得讲的，
      不只是技术栈。

      真正的工程工作，常常发生在正常流程之外。
      这些取舍决定了系统遇到异常时会做什么。

      01 / CONSISTENCY

      超时之后，
      先找证据，再做决定。

      网络中断可能发生在远端已接收之后。简单重试，看似恢复了服务，却可能制造第二笔订单。

      查看设计取舍 +

      处理方式

      请求前持久化意图，响应含糊时保留 unknown，随后查询订单与账户证据。

      付出的代价

      状态更多、即时可用性有所让步，但避免把不确定误判为失败。

      验证关注点

      重复请求、含糊响应、终态保护与对账幂等。

      02 / DATA INTEGRITY

      一个数字，
      连同它的单位与时间。

      金额精度、行情周期、时区与信息已知时间，都影响同一个数值该如何解释。

      查看设计取舍 +

      处理方式

      显式数据合同；固定精度存储在边界转换为业务单位；保留原始时间与数据质量。

      付出的代价

      增加转换和迁移检查，换取一致的数值语义。

      实现边界

      固定精度迁移的工作区实现与实际运行库升级分开验收。

      03 / RESILIENCE

      让异常可解释，
      让恢复有路径。

      常驻在本地的程序，迟早会遇到休眠、断网、重启或存储暂时不可用。

      查看设计取舍 +

      处理方式

      任务租约、执行权校验与有界重试；优先收敛未决订单，告警保留恢复证据。

      付出的代价

      恢复流程更复杂，但每一步都有可定位的状态。

      验证关注点

      崩溃恢复、并发归属、数据新鲜度与账本隔离。

      公开了什么？

      项目定位、技术架构、设计取舍，以及这一套纯前端合成演示的代码。

      哪些内容保持私有？

      核心业务源码、账户、持仓、订单、资金、策略参数、提示词、密钥、运行日志与原仓库历史。

      演示能证明什么？

      它帮助理解设计，不代表真实交易行为或策略有效性。测试、运行库迁移、长时运行与远程部署各自独立验收。

      这页会读取或上传我的信息吗？

      演示逻辑不读取文件、不请求业务接口、不使用统计脚本或浏览器存储。页面加载仍由 GitHub Pages 提供，遵循平台自身的隐私政策。
